## Article 1: Correctness first

1.1 **(W9)** The package's symmetric trimmed mean is trusted only when it **agrees with R's
`mean(x, trim)` on the same bytes**, by a rule written in the spec before measuring. R's computation is
deterministic, so the target is **exact agreement** (identical float64), with the conditions it assumes
(platform, R version, integer or double input) stated. A tolerance is a fallback only, and only one measured
in a spike (L-W8-04). A program makes the comparison. **[T]**
1.2 **(W9)** R's definition is learned **by running R**: how many observations are trimmed
(`floor(n * trim)`, including its floating-point behaviour), what happens at `trim >= 0.5`, negative trim,
missing values and empty input. Where the package deliberately differs from R (for example rejecting a
negative proportion that R silently ignores), the difference is a requirement, tested, and stated in the
README. **[T][Doc]**
1.3 Asymmetric trimming has no R built-in. Its definition is written in the spec, tested on hand-computed
cases, and cross-checked against the same definition evaluated in R; the README says it is our definition. **[T]**
1.4 Every number in the README (tables and headline) is generated by script from saved results; prose that
cites them is re-checked whenever results change. **[Doc]**
1.5 Statistical code is tested against **answers known independently of the code**: hand-computed small
cases, closed-form values, and R's saved output. **[T]**

## Article 2: Idiomatic, readable Go (McConnell 2004, ch. 32) **[C]**

2.1 Go modules; `gofmt` and `go vet` clean.
2.2 Meaningful, specific names; not abstract, not overly long.
2.3 No useless temporary variables or intermediate results.
2.4 Functions do one thing; large blocks become small, named functions.
2.5 Plain `if/else` and `for`; distribute the NOT in complex Boolean expressions.
2.6 Every exported identifier has a doc comment; comments explain *why*.
2.7 Errors are returned and handled; **no `panic`** for bad input (empty data, NaN, out-of-range
proportions, too many proportions).
2.8 **(W9)** The package **never changes the caller's slice** (it sorts a copy), and is safe for
concurrent use because it holds no state.

## Article 3: Test-first, measured **[T]**

3.1 Failing test before implementation of every critical component; **mutation check** important tests with
`go test -count=1`; a mutation that only breaks compilation does not count (L-W6-14, L-W8-03).
3.2 Standard `testing`; table-driven; tests need neither the internet nor R: R's results enter the Go tests
as **saved files with provenance**.
3.3 Benchmarks with `testing.B` and allocation reporting (`-benchmem`) for the package; a CPU and memory
profile of the program on the largest committed sample; the program logs what it did (structured, to
standard error).
3.4 **(W9)** Runnable **`Example` functions** document the package API and are checked by `go test`.
3.5 Guards, scripts and acceptance checks are themselves tested on a passing and a failing case; exit codes
are tested on the **built binary**, never through `go run`.

## Article 4: Clean, reusable design **[D]**

4.1 **(W9)** The trimmed mean is a **stand-alone, importable module** (`github.com/mioluigi/trimmedmean`)
with **no dependencies outside the standard library**, no printing, no logging and no `os.Exit`. One generic
API serves integers and floats.
4.2 **(W9)** The package is **versioned**: released by a semantic-version Git tag, so that `go get` fetches an
exact, verifiable version. A released tag is never moved.
4.3 The program repository is a thin layer: read data, validate input, call the package, report.
4.4 Pin every dependency version (`go.mod`, `go.sum`); `go.sum` is generated on Luis's Mac. **Never commit
`go.work` or a `replace` line** pointing at a local copy (L-W7-06). The R version is recorded with the results.

## Article 5: Documentation and Git hygiene **[Doc]**

5.1 **(W9)** **Each repository has a complete `README.md`.** The package's: what it computes, its exact
definition, install (`go get`), use (import and call), errors, limits, tests, licence. The program's: roles of

## 3. R's trimmed mean: what we expect, and the conditions (to be checked on the Mac)

From R's `mean.default` (to be confirmed by running it, constitution 1.2 and 9.3):

| # | Prediction | Condition it assumes | Checked by |
|---|---|---|---|
| P1 | R drops `floor(n * trim)` observations from **each** end, computed in float64, so `n = 100, trim = 0.29` drops **28**, not 29 (Go's float64 gives `100 * 0.29 = 28.999999999999996`, measured in the workspace) | R 4.4.2 `mean.default` | `semantics.tsv` rows `floor(...)`; `dropped_low` column |
| P2 | `trim >= 0.5` returns the **median**; a **negative** trim is silently ignored (no trimming); `NA` in the data gives `NA`; empty data gives `NaN`; a trim of length 2 is an error | same | `semantics.tsv` |
| P3 | **Integers agree exactly.** For integer samples the kept values sum exactly in float64, so the order of summation cannot matter | values well below 2^53 | `trimmed-means.tsv`, integer rows: Go value identical to R value |
| P4 | **Doubles may not agree to the last bit**, which is the riskiest assumption. R takes the kept values from a **partial sort** (`sort.int(x, partial = c(lo, hi))[lo:hi]`), so it adds them in an order that is not fully sorted; a Go implementation that sorts fully adds them in another order, and a floating-point sum depends on order. R's second pass (adding the mean deviation) should shrink any difference to a few units in the last place | arm64 Mac, where R's long double is 64 bits (`sizeof long double` in `r-session.txt`); Go uses R's two-pass mean | column `identical_to_full_sort` (R's built-in against R's own mean of the fully sorted kept values) |
| P5 | Integer and double input give the same R result for the same values | same | column `identical_as_double` |
| P6 | `mean(c(1e308, 1e308))` is `Inf` on the Mac (64-bit long double overflows) but would be `1e308` on an x86 machine with 80-bit long double: a platform difference, and a documented limit | arm64 | `semantics.tsv` |

**Decision rule for the spec, fixed now (before seeing the results).** If every double row has
`identical_to_full_sort = TRUE`, the comparison rule is **exact agreement** for all samples. If any row is
`FALSE`, the rule is exact for integers and, for doubles, agreement within a tolerance **measured** from those
rows (the largest relative difference found, times a safety factor stated in the spec), unless the spec
chooses to reproduce R's partial sort (open decision for the spec).

## Addendum A (2026-11-22 17:55): the first R capture stopped

- **What happened.** `capture-r.sh` stopped at `stopifnot(identical(values_read, values))`: a sample written
  with `%.17g` and read back by `as.numeric` was not identical to the values R generated. Nothing was committed.
- **Hypothesis, not yet shown.** R reads numbers with its own parser (`R_strtod`), which accumulates digits in
  a long double. The Mac probe shows `sizeof long double: 8`, so on this arm64 Mac the accumulation is plain
  double and a 17-digit string can come back one unit in the last place away. `testdata/r-reference/parse-check.tsv`
  counts, per float sample, the values whose 17-digit round trip fails, as evidence.
- **Change.** Floats are written with 4 decimals, as in Week 8; R computes from what it **read**; and R saves
  those doubles at 17 digits (`sprintf` is exact) in `testdata/r-reference/*-as-read-by-r.txt`, so a Go test
  proves Go's `strconv.ParseFloat` reads the same doubles from the sample files. Constitution 8.3 amended.
- **Lesson candidate.** A round-trip check that compares with the generator's memory tests the generator,
  not the shared file; compare what each side reads.

two-pass mean with R's overflow fallback. Comparison rule: **exact** for integers, for untrimmed doubles (Go,
like R, does not sort when nothing is trimmed) and for every asymmetric row (both sides sort fully); trimmed
symmetric doubles must equal **R's full-sort mean exactly** and R's built-in within **10⁻¹⁴ × the mean absolute
kept value** (20 times the measured worst gap). Reproducing R's partial sort is not worth tying the package to
R's internals for gaps of about two epsilons (Q7).

## 1. Problem

A Go consulting firm wants a first open-source package to show its craft: a **trimmed mean**, symmetric or
asymmetric, that any Go program can fetch with `go get` and trust. "Trust" means two things here: it agrees
with the reference implementation analysts already use (R's `mean(x, trim)`), and it refuses inputs where a
trimmed mean is undefined or misleading instead of returning a quiet wrong number.

## 2. Users

| User | Needs |
|---|---|
| **Go developer** (the firm's prospective client) | `go get` one module with no dependencies; one obvious function; clear errors; documentation with runnable examples |
| **Analyst moving from R** | Same answer as `mean(x, trim)` for symmetric trimming, and a written list of where the package deliberately differs |
| **Grader** | Two repositories, a README in each, instructions to get, use, build, run and test, and the Go-versus-R comparison |

## 3. Definitions

- **Proportions.** `low` and `high` are the proportions of the **sorted** observations removed from the lower
  and upper ends.
- **Counts.** For `n` observations: `dropLow = floor(n × low)`, `dropHigh = floor(n × high)`, computed in
  float64 exactly as R computes `floor(n * trim)`, so that `n = 100, trim = 0.29` drops 28 (spike P1).
- **Trimmed mean.** The arithmetic mean of `sorted[dropLow : n − dropHigh]`, computed **as R computes it**
  (spike addendum B): for **integer** types, one sum (exact below 2^53) divided by the count; for **float**
  types, R's two-pass mean (the first estimate plus the mean of the deviations from it), and, if the first
  sum overflows, R's fallback of adding each value divided by the count. When nothing is trimmed, the values
  are averaged in their given order, without sorting, as R does.
- **Symmetric** when only one proportion is given: `low = high = trim`. With `low = high`, this is R's
  `mean(x, trim)`. **Asymmetric** when two are given; R has no built-in, so this is **our** definition,
  evaluated in R the same way for cross-checking (spike §3).

## 4. Functional requirements — package (`trimmedmean`)

| ID | Requirement | Steps |
|---|---|---|
| FR-1 | `func Mean[T Number](values []T, proportions ...float64) (float64, error)`, where `Number` is every Go integer and floating-point type (including named types based on them). | S1, S2 |
| FR-2 | No proportion → the ordinary (untrimmed) mean; one → symmetric; two → `low`, `high`; more than two → `ErrProportionCount`. | S3, S4 |
| FR-3 | `values` is never modified; the function sorts a copy. | S2 |
| FR-4 | Errors are sentinel values usable with `errors.Is`: `ErrEmpty` (no values), `ErrNaN` (a NaN value), `ErrProportion` (a proportion that is NaN, negative, or not below 0.5), `ErrProportionCount`, `ErrNotFinite` (the result is NaN or infinite even after R's overflow fallback, e.g. `+Inf` and `−Inf` both kept). Each error message names the offending value. | S2 |
| FR-5 | Because each proportion is below 0.5, `dropLow + dropHigh < n`: at least one observation is always kept (tested at `n = 1, 2, 3`). The code still checks it and returns `ErrProportion`, because for very large `n` the float64 product `n × p` can round up to exactly `n/2`. | S2, S3 |
| FR-6 | The package prints nothing, logs nothing, never panics on any input, never calls `os.Exit`, holds no state, and is safe for concurrent use. | — |

## 7. Comparison rule with R (fixed before measuring; constitution 1.1)

Settled by spike 001 addendum B (R 4.4.2, aarch64-apple-darwin, 8-byte long double):

- **Exact agreement** (identical float64) for: every **integer** row; every **untrimmed** row; every
  **asymmetric** row (R evaluates our definition with a full sort, as Go does).
- **Trimmed symmetric float rows:** exact agreement with **R's mean of the fully sorted kept values**, **and**
  `|Go − R built-in| ≤ 10⁻¹⁴ × mean(|kept values|)`. Reason: R's built-in adds the kept values in the order its
  partial sort leaves them; the measured worst gap is 4.7 × 10⁻¹⁶ on that scale, so the limit is 20 times it.
- Go must read the samples as the same doubles R read: Go's parse of each sample equals R's saved
  `*-as-read-by-r.txt` value (a test).
- The comparison reports, per row: Go value, R value, difference in units in the last place (ULPs), and
  PASS/FAIL. A single FAIL makes the run exit 1.

## 8. Limits and consequences

### 8.1 Boundaries

| Item | Supported | Rejected, with message and exit code |
|---|---|---|
| Element types | all Go integer and float types | — (compile-time) |
| Number of values | 1 to memory limits (benchmarked to 10^6) | 0: `ErrEmpty` → program: `no numbers in FILE` · exit 2 |
| Proportions | each in [0, 0.5); one or two of them | NaN, < 0, ≥ 0.5: `ErrProportion` → `trim proportion 0.6 is outside [0, 0.5)` · exit 2; three or more: `ErrProportionCount` · exit 2 |
| Values | finite numbers; ±Inf allowed if the result is finite | NaN: `ErrNaN` · exit 2; NaN or infinite result: `ErrNotFinite` · exit 1 |
| Integer magnitude | exact when every value and the sum are below 2^53 in magnitude | beyond: still computed, documented loss of precision (README limit) |
| Input file | one number per line, optional `value` header | missing file, unreadable line (`line 7: "12abc" is not a number`) · exit 2 |
| Flags | `-data`, `-trim`, `-cpuprofile`, `-memprofile` | unknown flag, `-trim` without `-data`, malformed `-trim` · usage text · exit 2 |

### 8.2 Deliberate differences from R (README table)

| Case | R | This package | Why |
|---|---|---|---|
| negative trim | ignored, untrimmed mean | `ErrProportion` | a negative proportion is a caller mistake, not a request |
| trim ≥ 0.5 | returns the median | `ErrProportion` | a mean function that silently returns a median surprises callers |
| NA / NaN in data | `NA` | `ErrNaN` | an error says where; `NA` propagates silently |
| empty data | `NaN` | `ErrEmpty` | same |
| very large values whose sum overflows | R's fallback, a finite mean | same fallback, same result | no needless error |
| ±Inf kept, result NaN | `NaN` | `ErrNotFinite` | no silent NaN |

(Every R behaviour in this table is confirmed by `testdata/r-reference/semantics.tsv`, spike addendum B.)

### 8.3 Failure behaviour

- **Bad input:** rejected before any computation, with the line number or value; nothing written.
- **Partial failure (comparison mode):** every row is still compared and reported; the exit code says whether
  all agreed. `results/comparison.tsv` is written to a temporary file and renamed, so an interrupted or failed
  write never leaves a half file.
- **Interruption (Ctrl-C), full disk:** the program has nothing to clean up beyond the temporary file; a write
  error is reported with the path and exit 1.
- **Timeout:** not applicable (no network, bounded work).

### 8.4 Unintended consequences

| For | Risk | Guard |
|---|---|---|
| Data | the caller's slice reordered by sorting | FR-3, tested by comparing the input before and after |
| Data | personal data in committed samples | samples are synthetic, from a seeded script (constitution 8.3); data gate |
| Users | a misleading number (NaN, a median presented as a mean, silent precision loss) | FR-4, §8.2, the integer limit in the README |
| Users | believing asymmetric results are "R's" | README says asymmetric is our definition, cross-checked in R |
| External systems | a mistaken release cached forever by the Go module proxy | a tag is pushed only after the package's acceptance passes; never moved; a fix gets a new version (constitution 9.2) |

## 11. Open decisions (recommendation first)

| Q | Decision | Recommendation and reason |
|---|---|---|
| Q1 | API shape | **One variadic `Mean(values, proportions...)`**: it reads exactly like the assignment ("if only one argument is provided … symmetric"). Alternative: separate `Symmetric` and `Asymmetric` functions — clearer types, but two names for one idea. |
| Q2 | "Integers and/or floats" | **Generics (`[T Number]`)**: one function for every numeric slice, checked at compile time. A Go slice holds one type, so a mixed list is passed as `[]float64`. Alternative: `[]any`, which loses type safety. |
| Q3 | Infinite values | **Allow ±Inf; reject a NaN or infinite result (`ErrNotFinite`)**: trimming is meant to remove extreme values, and the error catches the only harmful case. Alternative: reject any non-finite value. |
| Q4 | trim ≥ 0.5 | **Reject (`ErrProportion`)** with a message that names R's median behaviour. Alternative: return the median as R does. |
| Q5 | Asymmetric flag syntax | **`-trim "low,high"`**, one flag mirroring the function. Alternative: `-low` and `-high`. |
| Q6 | First release version | **`v1.0.0`**, tagged once the package passes its acceptance (before R2); a fix found by R2 becomes `v1.0.1`. A firm's published offering signals a stable API. Alternative: `v0.1.0`. |
| Q7 | Float comparison rule | **As §7**, settled by spike evidence; reproducing R's partial sort is **not** recommended: it would tie the package's arithmetic to R's internals for a gap of about two machine epsilons. |
